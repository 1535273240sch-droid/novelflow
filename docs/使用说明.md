# NovelFlow 使用说明

> 桌面端小说写作工作台：接任意大模型，把写作 Skill 串成工作流，框架先行、章节有序、正文可导出。
> 界面为**羊皮卷 / 古墨文艺风格**（暖米色做旧纸底、松烟墨字、朱砂印章点缀）；本说明对应 **v1.1.0**。技术取舍见《DECISIONS.md》，进度与验收见《ROADMAP.md》，启动实测见《docs/实测基准.md》。

---

## 一、安装与启动

### 1. 从安装包（推荐给普通用户）

1. 到仓库的 **Releases** 页面下载 `NovelFlow-Setup-<版本>.exe`（Windows）。
2. 双击安装（可选择安装目录），完成后从开始菜单启动 NovelFlow。
3. macOS 版打包配置已提供（`npm run dist:mac` → `.dmg`），但**未在 macOS 真机验证**，请自行评估。

### 2. 从源码（开发者）

要求 Node.js ≥ 20（开发时使用 Node 22/24 验证）、npm。

```bash
git clone <本仓库地址>
cd novelflow
npm install            # 国内网络若 electron 二进制下载失败，见下方「常见问题」
npm run dev            # 开发模式（vite dev server + Electron 窗口）
npm run build && npm start   # 生产模式
npm test               # 单元测试（全 mock，不需要真实 API Key）
```

## 二、配置模型

1. 打开「设置」→「模型预设」→「+ 新建预设」，填写：
   - **名称**：随意，如「本地 mock」「DeepSeek」。
   - **协议**：`openai-compatible`（含 Ollama / LM Studio / 各类中转）或 `anthropic`。
   - **base_url**：OpenAI 兼容通常以 `/v1` 结尾；Anthropic 默认 `https://api.anthropic.com`。
   - **API Key**：仅经系统安全存储加密落盘，**绝不写入明文**；渲染进程永远拿不到密钥本身。
   - **模型名 / 上下文长度 / 默认温度 / 最大输出**。
2. 点「测试连接」：成功显示延迟，失败显示可读原因（401 / 429 / 超时 / 无法连接）。
3. 到「模型角色映射」把 **规划 / 写作 / 检查 / 润色** 四个角色各指向一个预设；Skill 会优先按其 `recommended_model` 取用对应角色。

> **不需要真实 Key 的联调**：`npm run mock` 起本地 mock 服务（默认 `http://127.0.0.1:8801`），
> 在预设里点「填入 mock」即可。故障注入见 README 的 mock 参数表。

## 三、项目即文件夹

新建/打开项目后，目录结构如下（可读、可备份、可用 Git 管理）：

```
<项目>/
├── novel.json            # 书名/题材/目标字数
├── bible/                # 故事框架
│   ├── 00-概述.md  01-世界观.md  02-人物/<角色>.md
│   └── 03-主线与卷纲.md  04-文风规范.md  05-时间线.md
├── outline/第NNN章.md    # 章节计划
├── chapters/第NNN章.md   # 正文
├── state/                # characters.json / foreshadowing.json / events.json
├── runs/runs.db          # 工作流运行记录（SQLite）
└── .history/             # 改写前自动快照
```

## 四、Skill

- 内置 8 个 Skill：生成故事框架 / 章节规划 / 正文写作 / 错别字与病句检查 / 润色 / 去AI味 / 一致性检查 / 状态回写。
- 顶栏「**Skill 库**」可查看、编辑、复制、导入、导出、删除；**编辑保存后版本号递增**。
- 提示词全部存放在仓库 `skills/` 目录（YAML 头 + 正文），业务代码零硬编码。
- **变量替换**：`{{chapter_text}}`、`{{selection}}`、`{{bible.文风规范}}` 等；缺变量会**明确报错并点名**。

### 在正文里用 Skill

1. 打开一个正文章节 → 右栏「Skill」标签。
2. 选 Skill、选模型预设、选目标（整章 / 选中文本）。
3. 点「**预览上下文**」可查看本次**实际发送**的变量与完整提示词。
4. 点「运行 Skill」：
   - **改写类**（润色 / 去AI味 / 正文写作）→ 差异视图，**逐处接受 / 拒绝**后「应用」；
   - **检查类**（错别字 / 一致性）→ 结构化清单（原文 → 建议 + 位置），逐条勾选后应用，**不直接改全文**。
5. 应用前会自动把原内容快照到 `.history/`，可随时找回。

## 五、故事框架与章节规划

1. 顶栏「**故事框架**」：填一句话灵感 / 题材 / 目标字数 → 生成 → 确认后「写入 bible/」。
   - 人物一节会按角色拆成 `bible/02-人物/<角色>.md`；模型漏节时不会覆盖已有文件。
2. **章节规划**：在 Skill 面板选「章节规划」运行，产物写入 `outline/第NNN章.md`。
3. **写正文门禁**：没有本章计划时，写正文会被**拒绝**并提示先去规划——这是硬门禁，防止模型脱离框架乱写。
4. **上下文组装**（写正文时自动进行，六条优先级）：
   ① 文风规范+世界观要点 → ② 本章计划 → ③ 出场人物档案（按计划按需）→ ④ 当前状态+未回收伏笔
   → ⑤ 前情摘要 → ⑥ 上一章结尾原文。超出 token 预算时按 ⑥→⑤→④→③ 裁剪，**①②永不裁剪**。
5. **状态回写**：写完一章运行「状态回写」，把人物状态变化、伏笔埋设/回收、关键事件合并进 `state/`；
   下一章的上下文会自动带上这些状态与未回收伏笔。

## 六、工作流

顶栏「**工作流**」：

- 工作流 = 有序节点卡片。每个节点四要素：**选 Skill → 选模型 → 绑定输入（上节点输出 / 项目文件 / 手填）→ 输出去向（下一节点 / 写文件 / 仅展示）**。
- 节点可**拖拽排序**（卡片左侧 `≡` 手柄）。
- 勾选「**人工确认点**」后，执行到该节点会暂停，可查看并**修改中间结果**再继续（未确认前不写盘）。
- 内置三个模板（只读，可一键复制为可编辑副本）：
  - **开新书（框架 → 规划）**
  - **写一章（7 节点）**：读取章节计划 → 正文写作 → 一致性检查 → 错别字 → 润色 → 去AI味 → 状态回写
  - **精修（错别字 → 润色 → 去AI味）**
- **失败语义**：停在该节点，已完成结果保留，可「从此节点重试」。
- **运行持久化**：运行记录写入项目内 `runs/runs.db`（SQLite）；**重启后**会提示「继续上次未完成的运行」。

## 七、导出与复制

- **复制全文**：章节顶部按钮，按设置里的复制格式输出，提示「已复制 N 字」。
  - 纯文本（去 Markdown 标记）/ Markdown / 网文格式（段首空两格、段间空行可配置）。
- **导出**：设置页「导出」→ 选范围（当前章 / 整卷区间 / 全书）与格式（`.txt` / `.md` / `.docx`）→ 导出。

---

## 八、外观与诊断

- 设置页「外观」：主题（浅色 = 羊皮卷 / 古墨，深色 = 玄墨夜读）、编辑器字号、行距。
- 设置页「诊断」：「一键导出诊断日志」（版本 / 运行环境 / 配置 / 主进程日志尾部，已脱敏）。
- 稳定性：渲染进程有全局错误边界；主进程 `uncaughtException` 记日志并保持窗口存活。

## 九、常见问题

**Q：`npm install` 时 electron 二进制下载失败？**
设镜像后重试：
```bash
# Windows PowerShell
$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'; npm install
```

**Q：模型「测试连接」失败？**
逐个排查：base_url 是否漏了 `/v1`、Key 是否正确、网络是否可达；429 表示限流（本应用会自动指数退避重试最多 3 次），5xx 会重试，连接类错误不会重试（配置错重试没意义）。

**Q：写正文按钮点了没反应？**
看提示——多半是**本章还没有章节计划**，先去「章节规划」生成 `outline/第NNN章.md`。

**Q：应用数据在哪？**
设置（含加密后的 Key）、Skill 库、工作流库都在系统用户数据目录下的 NovelFlow 目录；项目数据在你自己选的项目文件夹里。

**Q：支持 macOS 吗？**
打包配置已提供，但**未在 macOS 真机验证**；Windows 为本机验证平台。

## 十、已知局限（如实说明）

- 编辑器为纯文本 + Markdown 高亮；差异视图为**行级**（不做到字符级内联高亮）。
- 主进程代码改动需重启 `npm run dev`（未做主进程热重载）。
- Skill 运行历史未单独持久化（工作流运行记录已入库；单次 Skill 运行只保留在界面）。
- 启动基准测的是「冷启动到首屏」，不是「打开某个项目文件的耗时」，口径见《docs/实测基准.md》。
- macOS 打包配置未真机验证。
